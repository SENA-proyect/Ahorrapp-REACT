# RF-15 · Gestionar categorías financieras

## Propósito

Comprobar la consulta y gestión de categorías financieras, además de la protección de categorías globales, del sistema o pertenecientes a otra persona. Las respuestas de los servicios y las consultas a PostgreSQL se simulan, así que las pruebas no modifican datos reales.

## Archivos

- [`rf15.test.jsx`](rf15.test.jsx) prueba la interfaz React con Jest y React Testing Library en jsdom. Los métodos del servicio API son mocks controlados por cada caso.
- [`rf15.api.test.cjs`](rf15.api.test.cjs) monta las rutas reales de Express y les envía solicitudes mediante Supertest. `pool.query` y `pool.connect` simulan PostgreSQL.

## Entorno y estrategia

| Parte | Herramientas | Configuración |
|---|---|---|
| Interfaz web | Jest, React Testing Library, `user-event`, jsdom | `.test/jest.frontend.cjs` |
| API | Jest, Supertest, Express | `.test/jest.backend.cjs` |
| Persistencia | Mocks de `query` y `connect` | No se conecta a PostgreSQL real |

La interfaz real de categorías se renderiza, pero sus métodos de servicio se simulan para comprobar argumentos y resultados visibles. La API monta las rutas reales, crea un JWT para el usuario 7 y simula las respuestas de las consultas.

## Casos de prueba y resultados

La última ejecución registrada pasó cuatro pruebas de interfaz y cinco de API, para un total de **nueve aprobadas**.

### Interfaz web · `rf15.test.jsx`

Antes de cada caso se preparan respuestas para cinco módulos: gastos, ingresos, ahorros, imprevistos y deudas. La lista de gastos contiene una categoría global, una propia activa y una propia deshabilitada.

| Caso | Acción | Comprobaciones |
|---|---|---|
| Consulta y categorías globales | Carga categorías de gastos, ingresos, ahorros, imprevistos y deudas | Se llama una vez por módulo; la categoría global no expone acciones de edición, deshabilitación o eliminación |
| Alta y duplicados | Intenta “MASCOTAS” con espacios y luego “Educación” | El duplicado se rechaza sin llamar al servicio; el nombre válido se recorta y se muestra |
| Edición | Cambia “Mascotas” a “Veterinaria” | Se envía el ID y objeto esperados y la pantalla refleja el cambio |
| Estado y eliminación | Deshabilita, habilita y elimina “Viajes” después de confirmar | Se llaman los servicios correspondientes; cancelar no elimina y confirmar quita el registro de la vista |

### API · `rf15.api.test.cjs`

El token JWT representa al usuario con ID 7. Cada caso restablece los mocks de consulta y conexión.

| Grupo | Cantidad | Qué se verifica |
|---|---:|---|
| Autenticación | 1 | `GET` sin token responde `401` sin consultar la base |
| Nombre requerido | 1 | Nombre en blanco responde `400` antes de abrir conexión/transacción |
| Propiedad y categorías protegidas | 2 | `PATCH` y `DELETE` comprueban los filtros de usuario y categoría protegida; se responde `403` |
| Eliminación de categoría activa | 1 | Respuesta `409` si se intenta eliminar una categoría activa |
| **Total API** | **5** | |

## Trazabilidad con el requerimiento

| Comportamiento de RF-15 | Evidencia automatizada | Cobertura |
|---|---|---|
| Consultar categorías de módulos financieros | Se solicitan cinco tipos y se comprueba la categoría visible | Interfaz |
| Gestionar categorías personalizadas | Se comprueban alta, detección de duplicados, edición y cambios de estado | Interfaz |
| Proteger categorías globales o del sistema | La interfaz oculta acciones y la API verifica filtros de propiedad/protección | Interfaz y API |
| Evitar eliminación de categoría activa | La interfaz oculta esa acción y API responde `409` al intento directo | Interfaz y API |

## Ejecutar

Desde la raíz del repositorio, con las dependencias instaladas:

```powershell
npm test --prefix Frontend -- rf15
npm test --prefix Backend -- rf15
```

La primera orden ejecuta la suite de interfaz. La segunda ejecuta la suite de API. La ejecución registrada aprobó **nueve de nueve pruebas**.

## Alcance pendiente

Los mocks verifican qué operaciones solicita la interfaz y qué consultas arma la API, pero no verifican en PostgreSQL que deshabilitar conserve asociaciones ni que eliminar deje movimientos sin categoría. La matriz de cumplimiento de la rama de Juan describe el comportamiento funcional general de categorías y sirve como contexto, mientras que esta suite cubre los casos automatizados enumerados arriba.
