# RF-10 · Gestionar dependientes económicos

## Propósito

Comprobar que una persona autenticada pueda consultar y gestionar sus dependientes, y que la API valide los datos y limite cada registro a su titular. Esta carpeta contiene pruebas de interfaz y de API. Ambas usan datos y respuestas simuladas, por lo que no modifican una base PostgreSQL real.

## Archivos

- [`rf10.test.jsx`](rf10.test.jsx) prueba la pantalla React con Jest y React Testing Library en jsdom. `userEvent` simula clics y escritura, mientras que `fetch` se reemplaza por una función simulada.
- [`rf10.api.test.cjs`](rf10.api.test.cjs) monta las rutas reales de Express en una aplicación de prueba. Supertest envía solicitudes HTTP y `pool.query` simula PostgreSQL.

## Entorno y estrategia

| Parte | Herramientas | Configuración |
|---|---|---|
| Interfaz web | Jest, React Testing Library, `user-event`, jsdom | `.test/jest.frontend.cjs` |
| API | Jest, Supertest, Express | `.test/jest.backend.cjs` |
| Persistencia | Mock de `Backend/src/db/connection` | No se conecta a PostgreSQL real |

La prueba de interfaz renderiza el componente real `ModulosDependientes` y simula solicitudes `fetch`. La prueba de API monta las rutas reales de dependientes y reportes, firma un JWT de prueba y simula las respuestas de la base de datos. De este modo se prueban las reglas del componente, middleware y rutas, pero no la integración con infraestructura externa.

## Casos de prueba y resultados

La última ejecución registrada pasó las tres pruebas de interfaz y las doce pruebas de API, para un total de **15 aprobadas**.

### Interfaz web · `rf10.test.jsx`

La preparación guarda un token de prueba y hace que la primera llamada a `/api/dependientes` devuelva a Ana. También se sustituyen componentes de encabezado, notificaciones y alertas para aislar la pantalla.

| Caso | Acción | Comprobaciones |
|---|---|---|
| Consulta y alta | Carga a Ana y registra a Mateo desde el formulario | Token enviado en la consulta inicial, nombre sin espacios exteriores, datos esperados en `POST` y registro visible |
| Edición | Cambia el nombre de Ana a “Ana María” | Nombre actualizado en pantalla y `PUT /api/dependientes/12` con los datos editados |
| Eliminación | Cancela y luego confirma la eliminación | Cancelar conserva el registro y evita la solicitud. Confirmar envía `DELETE` y quita el registro de la vista |

### API · `rf10.api.test.cjs`

El token JWT de prueba representa al usuario con ID 7. Antes de cada caso se configura la clave JWT y se limpian las llamadas al mock de PostgreSQL.

| Grupo | Cantidad | Qué se verifica |
|---|---:|---|
| Autenticación | 1 | `GET` sin token responde `401` y no consulta la base |
| Validaciones de alta | 6 | Nombre y relación obligatorios, peso entero entre 1 y 5 y fecha real. Cada solicitud responde `400` antes de consultar la base |
| Alta y usuario titular | 1 | `POST` responde `201`; el ID de usuario se toma del token aunque el cuerpo envíe otro |
| Titularidad al editar y eliminar | 2 | `PUT` y `DELETE` filtran por ID de dependiente y usuario. El caso no autorizado responde `404` |
| Reporte por dependiente | 1 | Devuelve el rango consultado y totales agrupados, filtrados por usuario |
| Eliminación administrativa | 1 | Un usuario regular recibe `403` y no consulta la base |
| **Total API** | **12** | |

## Trazabilidad con el requerimiento

| Comportamiento de RF-10 | Evidencia automatizada | Cobertura |
|---|---|---|
| Consultar dependientes | La pantalla solicita la lista con token y muestra a Ana | Interfaz |
| Registrar y validar dependiente | El formulario envía los campos normalizados; la API comprueba campos requeridos, peso y fecha | Interfaz y API |
| Editar dependiente | El componente envía `PUT` al registro seleccionado; la API exige titularidad para actualizar | Interfaz y API |
| Eliminar dependiente | La interfaz distingue cancelar de confirmar; la API exige titularidad para eliminar | Interfaz y API |
| Proteger acciones administrativas | Se rechaza el uso de eliminación administrativa por usuario regular | API |
| Consultar gastos por dependiente | Se valida la consulta agregada por usuario y periodo | API |

## Ejecutar

Desde la raíz del repositorio, con las dependencias instaladas:

```powershell
npm test --prefix Frontend -- rf10
npm test --prefix Backend -- rf10
```

La primera orden ejecuta la suite de interfaz. La segunda ejecuta la suite de API, con seis variaciones de datos inválidos y dos métodos parametrizados para titularidad. La ejecución registrada aprobó **15 de 15 pruebas**.

## Alcance pendiente

Estas pruebas no comprueban persistencia real en PostgreSQL. Tampoco verifican desde el formulario la asociación de un gasto a un dependiente. La matriz de cumplimiento de la rama de Juan describe el comportamiento funcional general de RF-10, pero no reemplaza estas verificaciones automatizadas.
