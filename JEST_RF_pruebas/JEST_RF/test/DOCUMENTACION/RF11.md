## 2. Requerimiento verificado

Texto del documento de requisitos (las precondiciones se muestran en una sola línea):

> **RF-11: Generar reportes financieros.** El sistema deberá generar un informe consolidado, filtrable por rango de fechas y por período de presupuesto, que incluye: resumen, gastos por categoría y por dependiente, ingresos por categoría y por fuente, ahorros y su estado, deudas y su estado, imprevistos por categoría, fondo de emergencia y su estado, evolución temporal y ejecución del presupuesto. En la versión web el informe se descarga como PDF con tablas y gráficas; en la móvil la pantalla indica qué información se incluirá y el detalle se entrega en el PDF (RF-24).
>
> **Precondiciones:** El usuario ha iniciado sesión; Existe información registrada en al menos uno de los módulos financieros.
>
> **Requisitos específicos:**
> - **RF-11.1:** El informe es filtrable por rango de fechas y por período de presupuesto.
> - **RF-11.2:** Los reportes de rango exigen fecha de inicio y fecha de fin.
> - **RF-11.3:** Los reportes reflejan únicamente la información registrada por el usuario.
> - **RF-11.4:** La generación del informe no modifica los datos originales.
> - **RF-11.5:** Si una consulta parcial falla, el resto del informe se genera igualmente.
> - **RF-11.6:** Las secciones sin datos se omiten o se indican como “sin datos”.
> - **RF-11.7 (web):** El informe se descarga como PDF con tablas y gráficas.
> - **RF-11.8 (móvil):** La pantalla indica qué información se incluirá y el detalle se entrega en el PDF (RF-24).

## 3. Entorno y estrategia

| Elemento | Detalle |
|---|---|
| Pruebas de backend | Jest (`^30.5.2`) + Supertest (`^7.3.2`); configuración en `Backend/jest.config.js` y `test/backend/setupEnv.js` |
| Pruebas de frontend | Vitest (`^5.1.0`) + Testing Library (`react`, `user-event`, `jest-dom`) + jsdom; configuración en `Frontend/vite.config.js` (bloque `test`) y `Frontend/setupTests.js` |
| Comando backend | `npx jest rf11` (desde `Backend/`) |
| Comando frontend | `npx vitest run test/frontend/rf11` (desde `Frontend/`; `npm test` abre el modo observador) |

**Estrategia backend.** Se monta una aplicación Express con solo las rutas del módulo. La base de datos y los servicios dependientes están **simulados (mocks)**, por lo que no se accede a Supabase ni a Firebase. El token JWT se firma realmente, de modo que `verifyToken` se ejecuta sin simulación.

**Estrategia frontend.** Cada página se renderiza completa con Testing Library; `fetch` se reemplaza por un simulador (`test/frontend/helpers/fetchMock.js`) que responde por método y URL y registra las llamadas (URL, cabecera `Authorization` y cuerpo). El encabezado de navegación y los contextos de avisos se sustituyen por dobles. Se simula el teclado y los clics del usuario (`user-event`).

## 7. Observaciones y limitaciones

1. **Gráficas del PDF (RF-11.7).** Se verifica el contenido textual y tabular del PDF (ver RF-24); no se comprueba el dibujo de las gráficas, porque jsPDF está simulado.
2. **Móvil (RF-11.8).** La pantalla móvil no forma parte del proyecto entregado; solo se cubren backend y web.
3. **Fondo de emergencia inexistente.** El endpoint de rango responde 404 si el usuario no tiene fondo; el informe web lo absorbe (sección `null`), por lo que el 404 no es visible para el usuario final.
4. **Cálculos en SQL.** Las sumas y agrupaciones se ejecutan en PostgreSQL; con la BD simulada se verifican los parámetros (usuario y fechas) y el procesamiento posterior (balance, porcentajes), no los valores calculados por la base.
5. **Pruebas con BD y red simuladas.** Se verifica la lógica del controlador, los parámetros enviados a la base de datos y el comportamiento de las pantallas, pero no se ejecutan consultas reales ni se prueba contra PostgreSQL/Supabase; restricciones como los `CHECK` o el aislamiento por usuario a nivel SQL no se validan contra la base real.
6. **Precondición «cuenta activa».** En el código revisado solo se valida el token JWT; no se comprueba que la cuenta esté activa. No hay prueba asociada (se revisará junto con RF-09).
7. **Alcance.** Se cubren backend y frontend web. La aplicación móvil no forma parte del proyecto entregado y no se probó.
