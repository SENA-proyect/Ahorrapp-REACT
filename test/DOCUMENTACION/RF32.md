# AhorrApp · Documentación de pruebas

## RF-32: Inicio de sesión con Google — Backend (Jest) y Frontend (Vitest)

| | |
|---|---|
| **Requerimiento** | RF-32 · Inicio de sesión con Google |
| **Alcance de este documento** | Verificación de ID token, creación/autenticación de cuenta y sesión web |
| **Archivos de prueba** | `test/backend/rf32/inicio-google.test.js`; `test/frontend/Login.test.jsx`; `test/frontend/api.google.test.js` |
| **Resultado global** | **7 de 7 casos aprobados** |

---

## 1. Resumen

Se probó el flujo Google en tres niveles: validación del token en el backend, envío del token desde el servicio Frontend y guardado de sesión/navegación después de una autenticación exitosa.

| Capa | Escenarios | Pruebas | Aprobadas |
|---|---|:---:|:---:|
| Backend | Credenciales, token, alta de usuario y correo verificado | 4 | 4 |
| Frontend | Sesión/navegación y servicio HTTP exitoso/con error | 3 | 3 |
| **Total** | | **7** | **7** |

## 2. Requerimiento verificado

El usuario puede autenticarse con Google. El servidor valida el ID token con la audiencia configurada y solo crea o autentica una cuenta cuando Google devuelve una identidad y correo verificados. El Frontend conserva la sesión resultante.

### Código bajo prueba

| Archivo | Elementos |
|---|---|
| `Backend/src/routes/authRoutes.js` | Endpoint `POST /api/auth/google` |
| `Backend/src/db/connection.js` | Transacción y persistencia de cuenta nueva |
| `Frontend/src/pages/Login.jsx` | Inicio con Google, sesión y navegación |
| `Frontend/src/services/api.js` | Función `loginWithGoogle` |

## 3. Entorno y estrategia

| Elemento | Detalle |
|---|---|
| Backend | Jest y Supertest; `OAuth2Client` y base de datos simulados |
| Tokens | JWT de sesión se verifica con la clave de pruebas |
| Frontend | Vitest, jsdom y React Testing Library |
| Google Identity | Botón OAuth y respuesta HTTP simulados; no se accede a Google |

La verificación del proveedor se simula deliberadamente; los casos validan cómo la aplicación maneja sus respuestas y errores.


Desde `Frontend/`:

```powershell
npm test -- --run ../test/frontend/Login.test.jsx
npm test -- --run ../test/frontend/api.google.test.js
```

Resultado de la última ejecución: **7 pruebas aprobadas**.

## 7. Observaciones y limitaciones

1. No se usa un cliente OAuth real ni se contacta a Google; la verificación de ID token está simulada.
2. La base de datos está simulada; no se valida la creación de la cuenta en un entorno persistente.
3. La prueba confirma el flujo de la aplicación con respuestas controladas, no que el `VITE_GOOGLE_CLIENT_ID` de producción esté configurado correctamente.
